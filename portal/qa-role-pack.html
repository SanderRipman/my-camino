Rolle-QA er låst

Syntetisk testpakke

Test portalen som faktiske roller

Ny rollepakke oppretter eller oppdaterer fiktive @example.invalid-kontoer og sikrer staff-grants i minst én uke. Hver konto må sette opp sin egen Authenticator før sensitive AAL2-flater kan åpnes.

Ingen reelle data. Kontoene er kun koblet til DEMO-data. Midlertidige passord vises bare på denne siden når Opprett ny rollepakke returnerer dem. QA-siden lagrer ikke credentials i localStorage, sessionStorage eller IndexedDB, og passordene kan ikke hentes igjen herfra på en annen laptop. Kopiering bruker enhetens utklippstavle; tøm eventuell utklippstavlehistorikk etter testen.
Opprett ny rollepakkeBruk når du faktisk trenger en ny/oppdatert testpakke. Kan rotere midlertidige testpassord, men skal beholde nyttig syntetisk testhistorikk.
Forny én ukeBruk når eksisterende pakke bare trenger mer tid. Forlenger grants uten å endre passord, MFA eller eksisterende testdata.

Testrekkefølge

Reise + positiv og negativ tilgang

  1. Start med rollen slik den faktisk møter portalen: én tydelig neste handling, ikke dokumentmenyen.
  2. Følg N1→N2-handoff: interesse → mottak/triage → VÍA, uten å anta at interesse betyr godkjenning.
  3. Test riktig in-scope deltaker/pilot og følg indikator → kø → oppgave → kontekstfelt → eier/rute → riktig gate/skjema → tilbake.
  4. Forsøk en out-of-scope deltaker eller direkte URL og kontroller at låst tilgang ikke lekker informasjon eller blir blindvei.
  5. Test før og etter MFA/AAL2.
  6. Kontroller at formelle beslutninger går via riktig skjema/gate og ikke gjennom tilfeldig feltredigering.
  7. Kontroller SER fra mobilperspektiv: dagens etappe, kort innsjekk, pause/tilpasning og operativt minimum.
  8. Kontroller SER→VIDA: navngitt VIDA-eier, første handling innen 72 timer og én levende 14/30/90-plan.
  9. Noter alt som føles ulogisk selv om sikkerheten teknisk er korrekt.
